# ADR-0008: Exact pins and hash-verified installs

**Status:** Accepted  **Date:** 2026-09-10
**Enforced by:** `pip install --require-hashes` in Dockerfile and CI;
`pip-audit`; Trivy; Dependabot

## Context
Over seven years, the dependency graph is the largest attack surface and
the most likely source of "it built yesterday". Floating ranges make both
worse.

## Decision
`pyproject.toml` pins every dependency exactly. `requirements.lock` and
`requirements-dev.lock` are generated by one recorded `uv pip compile`
command with hashes. Installs require hashes. CI audits the production
lock and scans the image; Dependabot proposes updates weekly; a human
regenerates the locks quarterly (LONGEVITY §3).

## Alternatives rejected
- *Caret/tilde ranges.* Non-reproducible; a transitive bump can change
  behaviour with no diff in the repo.
- *Vendoring.* Reproducible but hides CVEs from scanners and bloats the
  repo.

## Consequences
Upgrades are deliberate diffs. Unused native dependencies are removed from
the default install (Kafka client moved to an extra, PR #10).
